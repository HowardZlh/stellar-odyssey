# 技术揭秘：星海奥德赛是怎么做出来的

> 面向好奇的读者与图形/前端工程师：本文用通俗方式讲清楚几个核心技术问题。
> 更工程化的架构约定见 [development.md](development.md)。

## 1. 一个场景如何跨越 10+ 个数量级？

从近观地球（相机距离几千公里）到可观测宇宙边界（465 亿光年），空间尺度跨越 10 个以上数量级。单精度浮点的深度缓冲在这种跨度下会彻底失效（z-fighting 满屏闪烁）。

解法组合：

- **对数深度缓冲**（logarithmic depth buffer）：Three.js 渲染器开启 `logarithmicDepthBuffer`，深度精度按对数分布，近处与极远处同时保持稳定；
- **连续层级插值**：滚轮驱动一个连续量 `continuousLevel`（1.0–4.0），四个视角层级（行星/太阳系/银河系/宇宙）的内容按该量交叉淡入淡出——不是"切换场景"，而是同一场景图里各层内容的透明度/挂载状态随缩放平滑过渡；
- **时间压缩比对数插值**：行星自转（小时级）与星系演化（亿年级）时间尺度相差十几个量级，各层级设定差异化时间压缩比，跨层级取对数插值，缩放过程中时间流速无跳变；
- **尺度标尺同步**：HUD 标尺单位（AU / 光年 / Mpc）随缩放自动换挡，由统一的尺度管理纯函数（`src/utils/scale.ts`）驱动。

## 2. 行星为什么"就在今天该在的位置"？

太阳系不是艺术摆位，而是真实轨道力学：

- 每颗行星使用 NASA JPL 的**开普勒轨道六要素**（半长轴/离心率/倾角/升交点经度/近日点幅角/平近点角，J2000 历元）；
- 每帧求解**开普勒方程** `M = E - e·sin E`（牛顿迭代），从平近点角得到真实位置——自动满足第二定律（近日点疾驰、远日点缓慢）；
- 打开应用时以真实当前日期推算初始相位，所以你看到的行星方位与今晚天文软件一致；
- 小行星带/柯伊伯带的每个粒子都有独立开普勒参数，在**顶点着色器**里推进——4 万+ 粒子零 CPU 开销，内圈快外圈慢的"开普勒剪切"自然涌现。

实现：`src/utils/physics.ts`（含完整单元测试）。

## 3. 体积星云：raymarch 发射-吸收积分

猎户座星云不是贴图，而是真正的**体积渲染**：

- 星云密度场烘焙为 **3D 纹理**（各维 ≤128），程序化基元（椭球壳/腔体/丝状扰动）组合出扇贝状发射腔、暗湾剪影等真实标志特征的相对方位与量级；
- 片元着色器沿视线 **raymarch**（最多 64 步），逐步累积发射-吸收积分（Beer-Lambert 消光 + 发射项），Hα 红 / OIII 青绿双色分层；
- **蓝噪声抖动**打散步进起点，用感知均匀的噪声换掉分层伪影；
- **半分辨率渲染目标**：体积层先渲到 1/2 分辨率 RT 再上采样合成，性能减半、观感几乎无损；
- **帧率自适应质量档**：3 秒滑动窗 FPS 低于阈值自动降步数（64→32）与 RT 分辨率，恢复后升档——低端设备平滑降质不跌帧（`src/utils/adaptiveQuality.ts`）。

## 4. 黑洞引力透镜：光子环是怎么弯出来的

推近人马座 A* 时的画面由专用 shader 生成：

- 以史瓦西度规下的光线弯折为蓝本做**屏幕空间近似偏转**：背景星场按到黑洞投影中心的距离反比扭曲，越近弯折越强，形成爱因斯坦环状拖曳；
- **光子环**：临界半径附近光线缠绕多圈的增亮环带；
- **吸积盘**：温度随半径按黑体谱定色（内热外冷），叠加**多普勒束流**（朝向观察者一侧增亮蓝移、远离一侧减暗红移）与**引力红移**——这正是 EHT 照片"上亮下暗"的物理来源；
- M87* 复刻 EHT 2019 形态：盘倾角 17° 近正视，跟随推近即触发。

shader 内的公式在 `src/utils/` 提供 **CPU 镜像函数**并配单元测试，断言 GPU/CPU 两侧常量同源——渲染代码也能被测试锚定。

## 5. 真实数据从哪来：离线烘焙管线

运行时**零外部网络请求**，但数据都是真的——秘密在构建期：

```
Gaia DR3 (TAP/ADQL) ──┐
SIMBAD ───────────────┤   scripts/bake-data/          public/data/
2MRS 目录 (VizieR) ────┼──> 拉取→校验→烘焙 ──────────> 静态产物 ≈2.5 MB
DSS2 影像 (hips2fits) ─┘   （幂等，产物随仓库提交）      （随应用分发）
```

- **昴星团**：Gaia DR3 按视差 + 自行共动选出 600 颗真实成员星，三维位置/星等/颜色全部真实；
- **宇宙背景**：2MASS 红移巡天 43,488 个星系的三维点云，红移按哈勃流换算距离——室女座团聚集、银道遮挡带都是数据本身的形状，整个目录仅 **2 次 draw call**（单 BufferGeometry + 顶点着色器）；
- **星系近观**：M31/M33/大小麦哲伦云的 DSS2 彩色影像被烘焙成密度/颜色/尘埃三张权重图，M31 按 77° 真实倾角**反投影回盘面**——运行时粒子云按图采样分布，旋臂和尘埃暗带与真实照片逐一对应；
- 每个产物写出前做数值域/计数/科学性自校验，meta 里登记来源、许可与检索语句；运行时加载失败自动降级为程序化路径。

## 6. 性能：60 FPS 是怎么守住的

| 手段 | 说明 |
|---|---|
| 渲染循环零分配 | `useFrame` 内禁止 new 对象，Vector3 等全部预分配复用；GC 毛刺消除 |
| 注册表模式绕过 React | 每帧位姿数据单写者写入注册表，渲染与相机解析直接消费——不经 React 状态、零重渲染 |
| 粒子走顶点着色器 | 银盘 4.3 万粒子、带内小行星、2MRS 点云的运动全部在 GPU 推进 |
| 细节层 LRU 池 | 黑洞透镜/体积星云/星系近观粒子等重资产按"跟随 + 距离阈值"懒挂载，四资源池各容量 1，逐出即 dispose——显存有账可查（`src/hooks/useDetailLayer.ts`） |
| 标签直改 DOM | 天体标签每帧直接改 transform，不触发 React 渲染 |
| 透明层次序注册表 | L4 所有透明层的 renderOrder 集中登记（`src/utils/universeRenderOrder.ts`），杜绝深度排序交叉导致的帧间闪烁 |
| 帧率自适应 | 见上文体积渲染质量档 |

实测：L4 巡游长跑 GC 后 JS 堆稳定在 ~50 MB，60 FPS 不跌破。

## 7. 一个 3D 应用如何做到 3,000+ 单元测试

原则是**纯函数先行**：一切可计算逻辑（轨道求解、尺度换算、事件域门控、动画曲线、质量档决策、展馆模式状态机）先写成 `src/utils/` 纯函数并配单测，组件只做接线。于是：

- 物理正确性可被断言（轨道参数区间、开普勒守恒）；
- shader 公式经 CPU 镜像函数锚定；
- 展馆模式是一个纯状态机（`src/utils/kiosk.ts`，覆盖率 100%），三态转移全部可枚举测试；
- 覆盖率 gate ≥90% 由 jest 配置强制，CI 不达标即失败。

UI/渲染类改动另走**无头 Chrome 视觉验收**：CDP 驱动按键/断言 DOM/截图比对，dev 钩子暴露 store 与显存账本供脚本化断言（见 [development.md](development.md)）。
